# Phase 7F — The five-agent demonstration

> **Offline, deterministic, labelled fixtures. No network, no deployment, no
> transaction.** Keys are derived from public labels and secure nothing.
> Run it with `npm run portfolio:demo`; its receipt, UI view and vectors are
> committed in [corpus/portfolio-demo-v1](../../corpus/portfolio-demo-v1/README.md)
> and regenerated by `npm run generated:check`.

**One authority layer. Many agents. Multiple markets.** One principal signs
one Portfolio Mandate: HYBRID allocation of 2,000 USDC of committed notional
across five agents, each with a different *shape* of authority. The agents
ask for 2,550. Four of them first want something they may not have.

## 1. Who is in it

| Agent | Domain | What its authority is about | Preferred | Hard max |
| --- | --- | --- | ---: | ---: |
| stock | Robinhood Chain (`robinhood-evm`) | canonical asset + exact representation + approved issuer, through the registry | 500 | 800 |
| swap | `swap-fixture` | venue, route, recipient, slippage | 250 | 500 |
| nft | `nft-fixture` | collection contract identity, not display name | 250 | 400 |
| yield | `yield-fixture` | product and issuer eligibility; quote freshness | 500 | 800 |
| perps | Lighter (`lighter-perp`) | leverage ≤ 3x; portfolio-wide derivative exposure | 500 | 600 |

Portfolio-wide limits: `portfolio-notional` 2,000 (every domain; the one
shared unit); `derivative-notional` 400 (perps only); `illiquid-notional` 400
(NFT only); `spot-capital` 800 (stock); `perp-margin` 400 (perps). Spot
capital and perp margin are separate resources and are never summed.

## 2. The run

| Round | Agent | Proposes | Outcome | Why |
| ---: | --- | --- | --- | --- |
| 1 | stock | 600 of a token with ticker `NVDA` at 122.50 | **REJECTED** | registry: `ISSUER_NOT_ALLOWED`, `SYNTHETIC_NOT_ALLOWED` — a registered look-alike from an unapproved issuer |
| 1 | swap | 300 through an unknown router quoting more WETH | **REJECTED** | `VENUE_NOT_ALLOWED` |
| 1 | nft | 350 for a "Mandate-Genesis" collection | **REJECTED** | `REPRESENTATION_NOT_ALLOWED`, `ASSET_NOT_ALLOWED` — same display name, another contract |
| 1 | yield | 700 into a 12.60 % vault | **REJECTED** | `REPRESENTATION_NOT_ALLOWED`, `ISSUER_NOT_ALLOWED`, `ASSET_NOT_ALLOWED`, `VENUE_NOT_ALLOWED` |
| 1 | perps | BTC long 2x, 600 notional | **REDUCE_REQUESTED** | `PORTFOLIO_LIMIT_EXCEEDED` on `derivative-notional`: locally valid, over the portfolio's 400 |
| 2 | nft | — releases its 250 (and its 400 illiquid) | applied | no authorized opportunity |
| 2 | stock | 600 of the approved note (4.8 × 125.00) | **ACCEPTED** | claims 100 of NFT's released 250 |
| 2 | swap | 300 through the approved router and pool | **ACCEPTED** | claims 50 of it |
| 2 | perps | 400 | **ACCEPTED** | derivative exposure exactly 400 |
| 2 | yield | 700 into the approved 5.20 % vault | **REDUCE_REQUESTED** | only 100 of the release is left: target 600 |
| 3 | yield | 600 | **ACCEPTED** | claims the last 100 |

The verifier re-derives all of it and every child is reserved through the
unchanged control engine: **1,900 of 2,000** `portfolio-notional` and 400 of
400 `derivative-notional` are held in the ledger. NFT's released 250 was
reassigned exactly once (100 + 50 + 100).

| Child | Reservation | Execution in this run | This run's evidence | Integration's evidence |
| --- | --- | --- | --- | --- |
| stock 600 | reserved | handed to `robinhood-gate-signer` | `OFFCHAIN_ONLY` | `LIVE_TESTNET` (Phase 7E.3) |
| swap 300 | reserved | `ADMIT_ATTEMPT`, then settled by the fixture venue | `SIMULATED` | `FIXTURE` |

**Transactions: 0.** All six refusals are `OFFCHAIN_REFUSAL`s: 0
transactions, 0 gas. If this run were executed live, the expected onchain
actions would be one gate `execute` on Robinhood Chain for the stock child and
one Lighter L2 order for perps; the fixture domains have no live counterpart.

## 3. The defenses behind the demonstration

The run shows the first layer refusing. The tests show the rest:

| Attack | Where it is refused | Test |
| --- | --- | --- |
| the stock agent buys a same-ticker look-alike | registry (room and verifier); Core: the binding cannot compile a market the gate does not list, and GateSpotPolicy / coverage refuse a hand-built one | `malicious.test.ts` |
| the swap agent substitutes the recipient | `RECIPIENT_NOT_ALLOWED`; Core refuses the action when the agent goes around the portfolio | `malicious.test.ts` |
| an agent asks beyond its hard maximum | `AGENT_LIMIT_EXCEEDED`; the ledger's agent leg refuses it around the portfolio | `malicious.test.ts` |
| the candidate is changed after authorization | `CHILD_ACTION_MUTATED` before any key; after signing, the gate: `AgentSignatureInvalid`, and with a compromised agent key `MaxNotionalExceeded` / `RecipientNotPrincipal` | `malicious.test.ts` (ONCHAIN_DEFENSE_TEST, SIMULATED against the Phase 6 reference model) |
| a stock reservation the portfolio never verified | the portfolio's guard in front of custody: the principal key never signs | `malicious.test.ts` |
| the room "accepts" a refused proposal, over-claims, forges a release | the verifier refuses each by name | `verifier.test.ts` |
| all five agents, at their hard maxima, at once | the room, the verifier, and the ledger under forced interleavings: ≤ 2,000 every time | `room.test.ts`, `verifier.test.ts`, `concurrency.test.ts` |

## 4. What is real, and what is not

| Real | Fixture or simulated |
| --- | --- |
| the Portfolio Mandate, derivation, room, verifier, receipt code | every address, price and quote |
| the existing registry, evaluating the stock representations | the registry snapshot's representations (the registry's own fixture convention: a real canonical identifier, fictional tokens) |
| GateSpotPolicy v1, the `robinhood-gate-signer` descriptor and the frozen Phase 6 gate's reference model | the offline gate configuration: a fixture market engineered to settle `USDC` (as in the 7E.3 cross-domain test), not the deployed testnet market, which settles `MDUSD` |
| PerpPolicy v1 over Lighter's recorded testnet market claims | the Lighter account book and prices |
| the control engine, the ledger, `ADMIT_ATTEMPT` | the swap, NFT and yield venues and their settlement |

The architecture is the proof; five live venues are not claimed.
