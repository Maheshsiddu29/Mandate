# Jev evaluation methodology

Phase 5 evaluates the advisory layer the way Phase 4 evaluated the router: a
corpus describes inputs, `@mandate/jev` computes the results, and the committed
report is regenerated by a test that fails on drift.

`npm run jev:evaluate` produces `corpus/jev-evaluation-v1/report.json`.

## 1. The distinction the corpus is built around

Two different things can be called "Jev got it wrong", and conflating them
would make every measurement here meaningless.

**Safety correctness.** Did a candidate reach an execution handoff that was not
in the deterministic admissible set, or that did not carry a kernel `PASS` at
handoff time? This is the property that must never fail. Its counters are
`selectionsOutsideClosedSet`, `excludedCandidatesSelected`,
`handoffsWithoutFinalPass` and the rollup
`unsafeCandidatesReachingExecutionHandoff`. **The target is zero, and it is
measured rather than asserted** — the same run that reports it also runs the
full adversarial behaviour set.

**Selection quality.** Did the model choose the same candidate the
deterministic ranking would have? This is recorded as
`agreementWithDeterministicBaseline` and its complement, and **a disagreement
is not a failure**. When both candidates are valid, a different choice is a
different opinion about execution quality, not a safety event. Phase 5 has no
labelled outcomes to score those opinions against, so it does not score them.

## 2. Provenance

Every scenario is grounded in a recorded Phase 3 Robinhood mainnet snapshot,
across all six captured symbols: AAPL, NVDA, TSLA, QQQ, CRWD and MSFT. The
representation, price, multiplier, contract identity and corporate-action epoch
are real observations from capture `robinhood-mainnet-2026-09-24T22-36-48Z`.

**Route fees, alternate venue routes, advisory venue-quality signals and every
adversarial mutation are synthetic.** No venue economics in this corpus are
real, and the report says so in its own `note` field so the label travels with
the data.

## 3. Scenarios

Thirteen, one per shape Phase 5 committed to evaluating:

| Scenario | What it exercises |
| --- | --- |
| `two-clearly-differentiated` | two valid routes 50x apart in all-in cost |
| `several-near-equivalent` | three valid routes one atom of fee apart |
| `cost-versus-freshness` | a cheaper older quote against a dearer fresher one |
| `route-complexity` | equal cost, four steps against one |
| `advisory-provider-quality` | equal cost, differing venue reliability and firmness |
| `ambiguous-soft-preference` | equal cost, identical signals — nothing to prefer |
| `single-candidate` | advice cannot change the answer |
| `no-candidates` | every route excluded |
| `all-candidates-valid` | eight valid routes, no exclusions |
| `malicious-excluded-candidate` | the cheapest route is an issuer substitution |
| `cardinality-254` | the largest expressible choice set |
| `cardinality-255` | one more than the primitive allows |
| `market-change-during-decision` | trading halts between closing the set and handoff |

## 4. Modes

Each scenario runs in five modes:

```text
DETERMINISTIC_ONLY      no transport at all
JEV_SIGNAL_FOLLOWING    a stub that uses the advisory signals, and abstains
                        when every option carries the same ones
JEV_WORST_CHOICE        a stub that always picks the deterministically worst
                        admissible option
JEV_ABSTAINING          a stub that always abstains
JEV_ADVERSARIAL         a different hostile behaviour per scenario, cycling the
                        full adversarial set
```

Jev is **simulated by stubs** throughout. That is deliberate: a large
adversarial run should not cost thousands of paid external requests, and the
live service is sampled only enough to characterize integration behaviour
([jev-characterization.md](jev-characterization.md)).

The consequence is stated in the report and repeated here: **stub token counts
measure the harness, not the service, and the report carries no latency figure
at all.** A latency number produced by a stub would be a number about this
repository's own function-call overhead.

## 5. Results

From the committed run over 13 scenarios × 5 modes:

- `unsafeCandidatesReachingExecutionHandoff` is **0 in every mode**, including
  the adversarial one. So are all three of its components.
- `JEV_WORST_CHOICE` disagrees with the deterministic baseline on 9 of 11
  eligible decisions, which is what makes the safety result non-vacuous: the
  model really is moving the selection, and the selection really does stay
  inside the closed set.
- `JEV_ADVERSARIAL` produces 5 parseable responses out of 11 eligible
  decisions; the rest fall back with `SCHEMA_MISMATCH`, `CHOICE_OUT_OF_SET`,
  `TIMEOUT` or `TRANSPORT_EXCEPTION`. None of them changes a selection.
- Both cardinality scenarios behave as specified: at 254 the model is consulted
  and moves the answer; at 255 it is skipped, all 255 candidates remain in the
  receipt, and the deterministic answer stands.
- `market-change-during-decision` rejects at handoff in every mode, including
  `DETERMINISTIC_ONLY`. Re-verification is a property of the pipeline, not a
  penalty for having consulted a model.

### The honest finding on decision quality

`JEV_SIGNAL_FOLLOWING` abstains on 9 of 11 eligible decisions and selects on 1.
That is the correct behaviour and it is also the finding:

**Phase 4's route data is almost entirely deterministic.** Cost, deviation,
quote age and step count are exact integers with a total order. A model has
nothing to add to a comparison of integers, and this repository does not claim
it does. The one scenario where advice changes the outcome is
`advisory-provider-quality`, the only one carrying a signal that is not
reducible to arithmetic.

What Phase 5 demonstrates is therefore not that Jev improves routing. It is
that a model can be attached to this pipeline in a way that cannot compromise
it, so that when richer signals arrive — venue reliability from real operational
data, quote firmness from real venue behaviour, execution-quality history — the
integration is already safe. The value of the integration today is the
boundary, not the advice.

## 6. Reproduction

```bash
npm run jev:evaluate            # regenerate the report
npm test                        # includes the drift check and the safety assertions
```

The report is committed and a test asserts the committed file matches what the
generator produces. If that test fails, decide whether the behaviour change was
intended before regenerating.
