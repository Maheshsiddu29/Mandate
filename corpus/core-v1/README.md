# Mandate Core v1 canonical-encoding corpus

Pins the canonical encoding and digest of every Mandate Core v1 object type
([docs/core-v1/implementation-7b.md](../../docs/core-v1/implementation-7b.md),
[ADR 0020](../../docs/adr/0020-mandate-core-package-and-encoding.md)).

> **Status: Phase 7B.** Generated by
> `packages/core/test/support/generate-core-corpus.ts`
> (`npm run core-corpus:generate`). `vectors.json` is committed;
> `packages/core/test/corpus.test.ts` and `npm run generated:check` fail if it
> drifts from the generator. It is an encoding corpus, not a decision corpus:
> no vector says whether anything is authorized.

## Format

| Section | Each entry |
| --- | --- |
| `tags` | object type → the domain tag its top-level encoding begins with |
| `vectors` | `id`, `type`, `description`, `input` (the validator's input, integers as decimal strings), `canonical` (hex of the tagged encoding), `digest` (keccak-256 of `canonical`, or `null` for the two receipt components that have no identity of their own) |
| `derivations` | identities Core derives rather than encodes as objects: `ReservationId` from `(actionId, generation)`, and the module-bound action payload digest |
| `negative` | `bytes` every conforming decoder must refuse, with the `error` code it must refuse them with |

A second implementation conforms when, for every vector, it validates
`input` to exactly `canonical` and `digest`, decodes `canonical` and re-encodes
it byte-identically, reproduces every derivation, and refuses every negative
entry with the stated code.

The error codes are provisional (open question 9 of the Phase 7A
specification) and may be renamed when the Core reason-code registry is
finalized; the refusals themselves are not provisional.

Venue, token and module names in the inputs are placeholders, as in
[examples.md](../../docs/core-v1/examples.md). Digests of manifests,
implementations and payloads are keccak-256 of readable labels, not of real
artifacts.
