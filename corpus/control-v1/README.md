# Mandate Core v1 control authorization corpus

Deterministic authorization vectors for the Phase 7D invariant and
reservation engine ([docs/core-v1/implementation-7d.md](../../docs/core-v1/implementation-7d.md)).

> **Status: Phase 7D.** Generated by
> `packages/control/test/support/generate-control-corpus.ts`
> (`npm run control-corpus:generate`). `vectors.json` is committed;
> `packages/control/test/corpus.test.ts` and `npm run generated:check` fail if
> it drifts from what the engine produces. It is a decision corpus over the
> **test-only synthetic reference module**: it pins how this engine decides
> on the synthetic module's semantics, not the behaviour of any real venue or
> product module (none exists yet).

## Vectors

| Id | Scenario | Required outcome |
| --- | --- | --- |
| `valid-authorization` | a 2,000 order under a 10,000 marked-exposure limit | `AUTHORIZED` |
| `missing-state` | the required mark is not supplied | `STATE_MISSING` |
| `stale-state` | the mark is 31 s old under `AGE 30 s` | `STATE_STALE` |
| `pending-reservation-refusal` | held 2,000 + pending 2,000 + proposed 2,000 > 5,000 | `INVARIANT_FAILED` |
| `global-invariant-refusal` | two roots; 1,500 held + 2,500 pending + 2,000 proposed > principal-global 5,000 | `INVARIANT_FAILED` |
| `semantic-narrowing-pass` | child ≤ 3x under parent ≤ 4x, proven by the owning module | `REGISTERED` |
| `semantic-widening-refusal` | child ≤ 5x under parent ≤ 4x | `DELEGATION_REFUSED` |
| `cas-conflict-reprojection` | two orders from one snapshot; the CAS loser re-projects and is refused | one `AUTHORIZED`, one `REFUSED` |
| `never-issued-closure` | examples.md §F: the mark moves after the reservation; revalidation fails; nothing was issued | `CLOSED` |

## Format

Each vector has `id`, `description`, `module` (the exact `ModuleRef` and
implementation digest the decision ran under), `outcome` and optional
`extra`. An authorization outcome records the authorization record id, Core's
`ExecutionAuthorizationId`, the `ReservationId` and generation, the
projection, invariant-results and charge-plan digests, the ledger versions
read and committed, the committed head, the lifetime and the number of state
bindings. A refusal records its code, reason, origin, path and, where
present, the invariant-results digest or the delegation violations.

Integers are decimal strings. Refusal codes are provisional (open question 9)
and may be renamed when the reason-code registry is finalized.
